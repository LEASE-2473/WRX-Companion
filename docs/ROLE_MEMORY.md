# 角色记忆（Phase 3）

侧栏「角色记忆」打开当前角色的常规、日记、自主活动、重要事件、外部世界书、设置六页。

## 内容来源与注入

- Layer 1：原始聊天。沿用上下文面板的历史条数，0 表示不发送旧历史，当前输入仍发送；不向量化。
- Layer 2：每日日记，SQLite `diaries`。
- Layer 3：实际自主活动的笔记，`ai_notes`。普通心跳不写此表。
- Layer 4：共同重要事件和约定，`shared_records`。
- Layer 5：外部知识书，`external_memory_chunks`，只能冷召回。

正文按来源保存。热＝每次发送；冷＝从向量检索后把命中内容注入。后台把当前会话／角色作用域内启用的热记忆与冷召回分别加入上下文，位于前部静态 system 设定之后、首条非 system 消息之前。冷召回失败不阻断主聊天，原因保存到请求 trace。

常规页统计 Layer 1–4 常驻内容的估算 Token：Layer 1 按最近 N 条旧历史（含应用时间标签）计入，0 为不注入旧历史；Layer 2–4 统计常驻拼接内容。历史条数入口位于日记左侧，沿用全局运行设置。展示分项、总量和提醒阈值，不静默裁剪；超限可减少历史条数或将 2–4 转冷。所有冷召回不设 Token 预算，仅使用相似度、Rerank 与最终召回条数。图片 Token 不含在文本估算中。

## 设置与第一次使用

1. 设置页为日记、自主活动笔记、重要事件分别填写独立 LLM 地址、模型、密钥、温度；不借用主聊天配置。提示词和 JSON 填表要求可独立编辑，事件任务保留输入设置；日记仅带时间的纯对话，无条数上限。
2. 配置 Embed；需要时启用 Rank。保存并测试按钮会实际调用相应 API。读取设置不返回明文密钥，留空保存保留已存密钥。
3. 日记页选择日期手动生成，重要事件页可提取当日事件或手动新增。独立任务日志展示状态、错误、原始输出和供应商 usage；不会出现在主聊天。
4. 开启每日任务后，独立调度器每五分钟检查；按各会话时区，在配置小时后结算前一天。任务以类型＋会话＋日期幂等，失败自动重试至少隔一小时；日记无聊天条数上限，模型上下文超限时递归二分总结并合并。长期停机遗漏的更早日期需要手动处理。
5. 日记默认满 7 天转冷；向量化成功才退出热区。单条 injection_mode=auto/hot/cold：auto 跟随规则，hot 手动常驻，cold 手动召回，可恢复自动规则。个人笔记与重要事件默认无时间自动转冷。
6. 外部知识书支持 TXT／Markdown 导入及独占行分隔符预切片；单个未切片长文本按 2000 字符窗口切分。导入不调用 API，随后手动向量化待处理切片。

默认预设参考 LEASE-Vector-Memory 的完整事件切片、真实来源、避免重复与事实记录原则，并针对 Companion 改为 JSON 输出。参考：https://github.com/LEASE-2473/LEASE-Vector-Memory/blob/main/prompt_manager.js 。没有复制酒馆脚本执行协议或角色扮演解限提示词。

## 状态与边界

- 每条记录保留稳定 ID、来源会话、作用域、日期时间、标签、来源消息／笔记 ID、冷热和向量模型签名。日记支持多个标签，重要事件必须恰好一个标签；界面以相同标签展示关联记录。
- 编辑正文使索引失效，内部记忆恢复热区，外部切片保持冷并等待重新向量化。更换 Embed 地址或模型后旧向量不参与召回，需要重新生成。
- 日记／重要事件输出先全部验证，再事务写入；任务输出与日志同事务落库。重要事件当前为新增候选＋人工编辑，不自动替换已有事件或判断完成／取消。
- `record_activity()` 留给 Phase 4 实际活动执行器：先落库实际结果，再尝试独立生成笔记；失败保留事实与错误状态。当前没有论坛／社交自主执行器，因此活动页初始为空。
- 设置当前为应用级配置；记忆正文按角色隔离，每条可选会话私有／角色共享。分支中新记录默认会话私有；用户主动选择角色共享会跨会话使用。
- 数据保存在原 SQLite 文件，正文、时间、作用域、关键词和注入策略已展开为实际列；关键词等数组仍用 JSON 编码。旧世界书与旧 JSON 向量工具不自动迁移。会话删除不会同步删除角色记忆，来源会话字段保留用于追溯。
- 本地 Token 为估算。未执行真实模型／Embed／Rank 调用，生成准确度和召回效果需配置后验收。日记自动生成和向量功能默认关闭。

上下文调试提供模拟拼接／预填充和上一轮真实实录。模拟复用正式编译器读取已保存配置，不调用模型／Embedding／搜索，不写入聊天；真实实录读取当前会话数据库请求记录。检查器按最终消息顺序展示 system／user／assistant、逐消息相对深度、文本 Token 估算与折叠正文；真实模式另外保留原始回复、整理文本、朗读文本和 Trace。

## 显式数据库结构（2026-10-02）

- `diaries`、`ai_notes`、`shared_records`、`external_memory_chunks` 主键为 `memory_id`；共同列：character_id、conversation_id、scope、content、keywords、injection_mode、occurred_at、created_at、updated_at。不存逐条 pinned／enabled；层级启用设置仍保留。
- diaries 增加 diary_date、timezone、entry_type、title、unresolved_hooks；daily_summary 为现有独立日记，chat_entry 仅预留类型，未接入聊天主动写入。
- ai_notes 增加 activity_id、activity_type、activity_content、execution_result、note_status、note_error；只由实际活动创建，外出功能继续封存。
- shared_records 增加 event_tag_id、record_type、status、due_at；事件状态仅存储，未实现自动更新／完成判断。
- event_tags 保存角色内稳定标签 ID 和名称；diary_event_tags 允许日记关联多个标签，事件仅一个标签。改标签名称不会改变关系。标签改名 UI 尚未提供。
- memory_sources 保存来源 ID；memory_vectors 独立保存向量、模型签名和索引状态。API 继续返回 id/date/tags/mode 等兼容字段；mode 是实际注入状态，injection_mode 是选择策略。编辑正文失效向量后内部记忆实际保留常驻，外部书等待索引。
- memory_schema.py 在事务 savepoint 内迁移旧 document JSON 表；失败回滚，重复启动幂等。旧 pinned 映射为 hot，旧 cold 映射为 cold，其余为 auto。旧逐条 enabled 不再参与使用；迁移前应备份。
- 本机迁移前使用 SQLite backup 保存 data/backups/companion-before-memory-schema-20261002-010310.sqlite3；业务表原本均为空，未新增日记／事件。备份含私人数据库，应仅本地保管。

## 2026-10-02 日记时间纠正

diaries不再保存occurred_at，日记按diary_date排序、展示和计算自动转冷日期；创建／修改时间由后端维护。API日记可只传date，不必传发生时间。完整字段及模型填写边界见根目录DATABASE_FIELDS.md。本节覆盖上文共同列中occurred_at对日记的描述，其余来源表保留发生时间。

## 2026-10-02 手动日记与应用内技能

日记页新增当日／即时生成，即时范围所选日期的起止时间段；独立日记Profile不隐式跟随主会话，日记及即时提示词可分别编辑。已保存的原始短默认自动升级，自定义保留，另提供载入新版按钮。当日材料变化后更新同一daily_summary，即时chat_entry另行保存。未知事件时间保存NULL。主聊天读目录、按需读技能、关键词查记忆／读全文及隐藏新增日记／事件已接入；事务、去重、来源、取消及重新生成保护见根目录SKILLS.md。上文关于chat_entry未接入及事件时间兼容值的旧描述以本节为准。

## 2026-10-02 日记范围更新

手动与自动当日日记统一读所选日全部纯对话；手动即时日记由date、start_time、end_time选择单日时间段，按会话时区含开始不含结束，结束可为24:00。废止recent_messages范围。日记只输入时间、说话方、纯文本及角色名，不注入图片、搜索结果对象、情绪、活动笔记或已有事件；正文中的真实讨论保留。

先完整总结，确切上下文超限才二分两份各自总结，再合并；子份超限继续拆，单条长文本也支持拆分。普通错误不触发拆分，合并不再缩短则报错，完整成功前不写入日记。任务calls显示阶段与成功调用用量，总usage为成功调用累计（缺项保持未知）。失败请求未返回用量无法计入。技能日记直接依据主模型本轮实际收到的全部上下文，围绕近期话题自主挑选主题，不限最近条数、不强制全量复述。

## 日记标题与管理（2026-10-02）

日记模型返回title、content、tags和可选unresolved_hooks；title是简短主题，不含日期；正文选择一至三个主线，不逐消息复述，默认三至六段、约五百至一千字；标签仅核心主题。主聊天日记技能也允许title，旧模型缺少标题时兼容为空，界面显示未命名日记。列表日期在最左侧，随后标题、类型与使用状态；展开可编辑标题／正文／标签并保存。

DELETE /api/role-memory/{character_id}/diary/{memory_id}按角色校验归属；删除将完整记忆（含标签、来源与向量）写入本地deleted_memories恢复表，再移出diaries，清理来源／索引／标签关联，重建该会话最新每日未结话题。关联生成任务标为deleted，允许同材料重生成。deleted_memories字段为memory_id、deleted_at、document，均后端填写，不参与注入或检索；暂未提供恢复UI，可从副本恢复。

## Layer 1时间范围（2026-10-02）

常规页选择从指定时间开始，设置日期与时间（按当前会话时区，包含该时刻），即可预览选中消息条数与估算Token；输入变更自动预览，也可点预览范围。保存后下一轮主聊天使用同一规则，时间模式无条数上限。设置仍全局，旧配置默认最近条数，用户可切回；未知时间记录只在条数模式可选。预览不调用模型、不删除聊天，不含图片Token、本轮输入与其他提示词。

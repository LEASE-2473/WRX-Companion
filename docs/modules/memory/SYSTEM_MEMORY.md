# 系统记忆与角色日记

更新日期：2026-10-04。本文为现行说明。

## 使用方式

记忆总结提示词统一放在[app/memory/prompts/](../../../app/memory/prompts)（[提示词映射](PROMPTS.md)），系统四表自动／追溯共用system.md，当日日记用diary.md，指定时段用diary_instant.md，聊天自主日记技能在app/skills/definitions/diary-write/SKILL.md；每个请求的输出格式直接包含在对应文件；长材料合并是单独请求，使用完整的diary_merge.md。直接编辑UTF-8 Markdown，页面保存也写回相同文件。既有自定义文本已从SQLite迁出，不保存多版本Prompt Profile；首次更新需重启应用，之后编辑在新任务生效，运行中追溯使用启动时文本。

左侧新增“系统记忆”，五个分页为聊天总结、人物记忆、物品、约定、外部世界书。维持现有浅色绿色风格，手机使用内部横向表格滚动，表格支持编辑、删除、转冷／转热。

在“自动填表与提示词”选择对话用途模型；留空沿用日记任务模型。总结间隔默认60分钟，批次请求间隔默认2秒。自动填表默认关闭，保存启用后由后端每5分钟检查一次，不依赖网页保持打开。间隔按消息显示时间划分，而不是按消息条数。

首次自动任务从启用后的最近一个完整周期开始，更早历史通过追溯填表。后台停止期间不运行；恢复后继续处理完整窗口，每次调度一个窗口，避免集中请求。修改间隔影响后续窗口。

追溯可以一次选择多天，系统按设置的分钟数拆成连续窗口，串行发LLM请求，并在批次之间等待。开始包含、结束不包含，未带时区的选择值按当前会话时区解释。失败立即停止，显示失败原因；停止保留已完成批次。重新扫描原范围可跳过已完成且原始材料未改变的批次。重启会把在途批次标记为中断，需重新发起追溯。

系统四表统一绑定角色，跨同一角色的所有会话；来源会话只用于追溯材料。切换会话不会丢失角色记忆，其他角色不可读取。会话ID表示来源与可选会话绑定，不把记忆生命周期绑在会话上；删除会话不会删除已形成的系统记忆。原始对话删除后无法再次重建，编辑原对话不会自动撤销已经总结的事实。

## 外部世界书

外部世界书统一在系统记忆第五个分页管理，支持TXT／Markdown或粘贴导入、自定义切片分隔符、角色／会话绑定、正文／标签／关键词编辑、单条与批量向量化。已有资料沿用external_memory_chunks与原稳定ID，无需搬表或重新导入，召回方式不变；不参与自动填表。Embedding／Rerank配置与日记和系统表共享，目前仍从角色记忆设置页配置。

## 四类表格规则

| 表 | 模型填写 | 后端规则 |
|---|---|---|
| 聊天总结 | content、tag | 追加，后台写来源时间段 |
| 人物记忆 | name、relationship、history、impression | 按姓名合并；历史事件追加，关系和用户印象更新，缺失字段不覆盖 |
| 物品 | name、description、location | 按名称合并；描述和位置更新，缺失字段不覆盖 |
| 约定 | content | 追加并按相同正文去重，后台写约定的来源时间段 |

“约定时间段”是达成该约定的聊天窗口。明确的履行时间保留在概述中，模型不能推断没有证据的时间。人物与物品的时间段保留首次来源窗口，不增加额外创建、修改、访问、过期时间字段。

默认提示词要求第三人称客观描述，区分明确事实、计划与未知，不推测心理、不执行历史材料中的指令。仅接受JSON数据，不执行SQL／脚本。整批输出验证后用SQLite事务提交，任一无效行或串表字段使整批回滚。请求期间有人编辑热表时，拒绝旧模型输出以避免覆盖手动修改。

模型只能更新热记录；冷行不提供给填表模型，同名冷行需转热后再更新。转冷要先成功生成向量；失败保持热记录。修改文本清除旧向量；手动编辑冷记录会恢复热状态。热记录直接注入聊天并纳入热区Token估算，冷记录使用现有Embedding／Rerank召回配置；关闭向量时系统冷记录回到直接注入。关键词记忆读取技能也可查询系统表。

## 日记与旧记忆迁移

日记是陪伴角色第一人称回顾，有独立提示词和模型设置。选择当日或指定日内时间段时，后台直接读SQLite messages原始消息，不走聊天history_selection，不受最近N条／起始时间过滤影响。默认角色绑定会汇集该角色各会话材料，分支中的同时间、同角色、同正文副本去重。没有显示时间的旧消息不虚构时间，不能进入指定时间窗口。

每日自动日记按角色去重，同角色同日的手动每日生成更新同一记录。即时聊天日记仍是AI自主写入的小段感受，不能当成选定整日范围的独立总结。AI聊天技能仅保留日记写入与记忆读取，不再提供共同事件／约定写入。

一次性迁移将已有记忆作用域改为角色共享，旧shared_records中的agreement删除并清除来源、向量，不创建恢复备份；标记完成后不会再重复删除。旧非约定事件保留原表供历史兼容，但退出界面、常驻和冷召回路径。自主活动与外部知识书继续使用已有存储和能力。

## SQLite与模块

系统四个分页对应四张独立物理表，sequence自增序号为唯一持久身份，各业务列独立，不保存document或随机系统ID。`system_memory_batches`仅保留批次id、角色／会话／作用域、来源时间段、status、error；幂等id含窗口及原始材料摘要。

- app/memory/system.py：时间选择、分批任务、验证／事务、冷热与调度。
- app/memory/system_routes.py：设置、追溯／停止、进度、表格编辑与删除API。
- app/static/memory/system-memory.js/css：紧凑表格分页界面。
- app/memory/role.py、app/memory/schema.py：角色作用域迁移、独立日记与召回整合。

任务锁和进度在单个应用进程中；当前支持单worker部署。重启不自动恢复人工追溯请求。真实LLM可能返回非法JSON、遗漏事实或超过上下文上限，此时系统批次明确失败，不截断材料或部分保存；可减小间隔后重试。离线测试不代表真实模型总结质量验收。

参考：用户指定本地ST-Memory-Context-main的prompt_manager.js与backfill_manager.js（追加／更新、串行分批和间隔）。公开LEASE-Vector-Memory最新版本已删除自动总结，因此本实现以用户给定的四表和时间规则为准，没有复制其楼层驱动机制。


## 四张物理表与向量状态（2026-10-04）

四表为system_summary、system_people、system_items、system_agreements（统一system_前缀）。每表只有sequence自增主键、character_id、conversation_id、range_start／range_end、对应分页的业务列、mode、vector BLOB、vector_signature和虚拟派生vectorized。没有随机系统记忆ID、document、scope、kind、生成／更新时间或不适用业务列。API的id为“类型:序号”，仅计算，不写入数据库；各表序号可以相同，不会串表。

人物／物品保留首次来源会话与来源时间段，历史追加及属性刷新不另造时间字段。角色共享记录不因来源会话删除而删除。system_memory_batches仍为独立批次去重／恢复表，其任务键不是记忆ID。

mode决定直接注入或检索；SQL的vectorized为vector存在与否的VIRTUAL派生列，不重复保存布尔状态。网页vectorized另校验当前Embedding签名，表示当前可用。签名用于模型／端点变更时拒绝旧向量，不能删除。每条系统记录直接构成一条召回候选，不依赖外部世界书切片库。候选参与召回不保证最终入选，仍受相似度阈值、Top N及Rerank影响。

转冷需先获得非空、有限、非零向量并事务保存；失败保持原状态。编辑清除向量并转热；向量关闭或模型签名失配时冷记录回到直接注入，避免从上下文与召回同时消失。首次启动以事务迁移旧system_memories内容并删除旧表，旧随机ID不保留；旧会话绑定统一变为角色共享，坏向量恢复热状态。

# 全局用户信息与画像

WRX只有一个用户：用户信息全局共享，角色保留人格与模型绑定，会话保留对话记录。侧栏「用户信息」管理称呼、核心资料、标签画像、候选和后台整理。

- 称呼用于聊天显示、`{{user}}`宏、系统记忆和日记总结。替换作用于发送模型的提示词，不改写历史正文。已有总结不自动重写。
- 核心资料每轮始终注入，预设关闭userDefinitions也不会关闭核心资料。角色中旧user_name和persona只保留迁移兼容，不再作为实时用户资料来源。
- 标签包括关键词和总结；仅当前用户发言与已选历史中上一条用户发言匹配关键词时注入，共两轮用户发言。AI回复不参与触发或续期，再早的用户发言不参与。空关键词的标签只保存。此为轻量关键词激活，尚无BM25、向量、多路融合与rerank改造。
- 首次加载时唯一旧称呼和唯一旧介绍迁移为全局资料；多份冲突旧资料进入候选，保留旧角色原字段，不猜测哪份正确。迁移只执行一次。

## 目录与职责

- app/user/models.py：资料和标签校验，不调用模型。
- app/user/store.py：全局资料、候选、每日任务状态、旧数据升级；复用chat/store.database，不新建数据库。
- app/user/context.py：纯函数，只接收快照，匹配当前和上一轮用户发言，不读取文件或调用模型。
- app/user/service.py：当日完整材料整理、模型输出校验、并发保护、每日调度。
- app/user/routes.py：HTTP入口，委托store/service；原/api/user-profile路径不变。
- app/user/prompt_files.py与prompts/profile_summary.md：独立用户运行提示词；只升级精确匹配旧默认的配置，保留自定义提示词。选词通常2–5个，避免包含关系和大小写冗余，此为模型约束而非程序硬上限。
- app/static/user/user-profile.js与.css：用户界面与专属样式，不再混入通用settings样式。
- tests/user/test_user_profile.py：该功能的隔离回归。

main注册路由，lifecycle恢复与启停调度；chat/core调用用户存储与纯context，memory和character只读取全局资料。共享正文清理归common/dialogue，用户模块不依赖角色日记实现。skills保留目录、XML白名单和成功事务编排，候选实际保存交给user/store。

SQLite的settings.global_user_profile、user_profile_candidates、user_profile_jobs均保留原位及原字段，移动源码不迁移私人数据。无旧模块转发壳。

## 候选技能

`profile-update`默认启用、按需读取。主模型仅追加用户明确强调的新信息，不直接修改正式画像。协议继续使用普通文本XML，无供应商原生tool calling。

首次请求携带技能目录，模型可独立输出read_skill；第二次携带技能正文和读取结果，模型输出聊天正文及append_profile_candidate。读取本技能后禁止再次读取，因此该技能路径最多两次模型请求；配置为直接提供正文时可一次完成。原有memory-read读取限制没有修改。

候选随成功聊天事务保存，按request_id/action_index去重；重生成和编辑重发不追加，取消或失败不提交。候选与正式标签在界面分开显示，候选可忽略。

## 后台整理

默认关闭。独立选择已有LLM Profile，留空跟随全局LLM，不跟随某个角色。可编辑总结提示词，输出约定为user_profile XML内的完整entries JSON列表。

启用后每分钟检查；北京时间指定小时后整理前一天，发送完整用户画像、待整理候选和该日所有角色、会话的完整文本对话，不按聊天history_depth截断。分支中相同来源、角色和正文去重，图片不发送。未知时间的旧消息无法归入某日。停机跨越多天时仅整理启动时的前一天，其他日期可手动处理。

后台只能替换标签entries，用户手填称呼和核心资料保持不变。整理中手动编辑或忽略候选会使旧结果失效；新追加的候选留待后续整理。成功后本次快照候选标为已审阅；失败、中断、格式错误和过量条目不覆盖正式画像。

每天自动最多尝试一次，失败可手动重试；已成功日期不重复运行。超时180秒。完整材料超过模型上下文时会失败并保留资料，不偷偷截断，也不自动增加多次模型请求。此实现沿用单worker约定。

## 验证与上线

tests/user/test_user_profile.py覆盖全局作用域、迁移冲突、关键词注入、候选幂等、重生成、技能停用、两次请求、全量跨角色材料、失败和并发保护。真实模型输出质量与超大历史仍需上线验收。

后端需重启、页面需刷新；这时首次读取才迁移正式库。开发验收使用独立SQLite和模拟模型，不自动开启每日整理。

## 跨服务器导入与导出

用户资料存SQLite，直接把JSON放data目录不会自动导入。用户信息顶部「导出JSON」下载已保存的name、core、entries，不包含模型配置与密钥。「导入JSON」选择文件、确认后立即保存，无需再逐项填写；会替换称呼、核心与全部正式标签，保留目标服务器模型／每日设置、候选及任务记录。支持简单资料JSON、完整Profile JSON和profile包装的导出快照，但仅导入三项资料。

服务端校验格式与revision，冲突需重新打开再导入；写入前在settings.global_user_profile_import_backup保留最近一次导入前完整配置，与导入处于同一事务。文件最多5MB；导出只读已保存资料，未保存编辑应先保存。另一台服务器需先部署含此功能的app代码、重启后端并刷新网页，再选JSON文件导入。不要用整个companion.sqlite3覆盖另一台服务器的聊天库。
